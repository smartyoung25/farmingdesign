# 뮤테이션 스크립트 — 차수 가드가 헛돌지 않는지 다시 잰다

매 차수는 가드(테스트)를 만들고, 그 가드를 **일부러 깨서**(코드·문서를 한 곳씩 바꿔서) 잡히는지 잰다 — 차수로그의
「뮤테이션 N/N 잡음」이 그 기록이다. 265차까지 이 스크립트들은 작업 임시 폴더에만 있어 **리포만으로는 재현할 수 없었다**
(레드팀 32회차 지적). 265차에 223~264차 스크립트를 **당시 내용 그대로** 옮기고(절대 경로만 리포 기준으로), 공통 실행기를 붙였다.

```bash
python mutations/run_all.py            # 전부 — 약 10분(스크립트마다 pytest를 여러 번 돈다)
python mutations/run_all.py 262 263    # 지정한 차수만
```

## 실행기(`run_all.py`)가 하는 일

1. **원본 통과 확인** — 스크립트가 부르는 테스트 파일과 `-k` 선택자를 모아 먼저 돌린다. 실패하면 그 스크립트는 **무효**로 보고한다
   (254차 교훈 — 원본이 실패한 채 「5/5 잡음」이 나왔다).
2. **안전 복원** — 스크립트가 이름으로 부르는 리포 파일을 실행 전에 바이트 그대로 저장하고, 끝나면(시간 초과·중단 포함) 되돌린다.
3. **집계** — 「잡음」·「놓침」·「적용불가」를 센다.
   - **놓침**: 그 가드가 지금은 그 변형을 못 잡는다 → **새 결함이면 가드를 고친다**. 결함이 아닌 것은 `KNOWN`에 **분류와 이유**를 달아 둔다
     (등가 변이 · 대상 이동 · 상태 변화). `KNOWN`에 없는 놓침이 있으면 종료 코드 1.
   - **적용불가**: 그 뒤 차수가 대상 문구를 바꿔 옛 패턴이 더는 없다 — 당시에는 적용됐다(차수로그 기록). **낡음**이지 실패가 아니다.

⚠️ 스크립트에는 엔진 키·케이스 식별자처럼 **내부 데이터의 실명**이 문자열로 들어 있다 — 변형할 대상 문구가 그것이라서다.
내부 기록은 이름을 유지한다는 경계(183차 · ★260차 결정)를 따른다. 새 스크립트의 **설명 문구**는 표시 코드로 쓴다.
