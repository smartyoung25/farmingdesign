## 1. 목적
- 메뉴가 만든 쪽의 언어(기능 지도 · 산출물 코드)로 되어 있다. 농업인·투자자·공공기관이 **자기 질문으로 들어오는 입구** 3개를 만든다.
- 서비스 드롭다운이 건너뛰는 **공통·근거 기능 9종**의 이름을 메뉴에 드러낸다.

## 2. 배경·사용자
- 273차 점검(`근거_콘솔점검_20260929.md` 2절·6절):
  - 산출물 27종 = 기본디자인 5 · 시방·사양 5 · 발주·계약 8 · **공통·근거 9**. 드롭다운이 공통·근거를 건너뛰어 **7종은 메뉴 어디에도 이름이 없다**(근거대장·판정 부록만 다른 경로로 보인다).
  - 농업인 — 기본디자인 5종이 답을 내는데 **입구가 없다**. 투자자 — 투자 실사 카드·재무 시나리오가 공통·근거라 **안 보인다**. 공공기관 — 269차 확보 지침의 가점 항목이 **「설계도서 준비 여부」**인데 산출물과 **연결이 없다**.
- 사용자: 콘솔을 처음 여는 세 부류.

## 3. 범위
- 포함:
  - 관점 3개(농업인·투자자·공공기관) 정의 상수 1개 — 각 관점이 **어떤 산출물 코드를 묶어 보는가**
  - 관점 화면 3개 + 상단 메뉴
  - 서비스 드롭다운에 **공통·근거 9종 노출**
  - 공공기관 관점에서 2026년 지침 가점 항목과 우리 산출물의 **이름 대조표**(값·판정 없이)
  - 가드 테스트 1건
- 제외 (이번에 하지 않음):
  - **관점별 추천·판정**(「당신에겐 이것이 맞다」 금지)
  - 주소·품목·면적만 받는 기본설계 입구(별도 지시서로 — 엔진 도달률 문제가 선행)
  - 가격·요율·밴드 표시(시세성·판단성)
  - 기존 홈·케이스 화면 구성 변경

## 4. 입력·출력
- 입력: `FUNCTION_OF_CODE` · `function_index()` · 269차 근거 문서의 가점 항목 원문.
- 출력: 관점별 화면 3개. 각 화면은 **묶음과 이유**만 낸다.
- 관점과 산출물 코드의 배정은 **상수 한 곳**에 두고 화면은 읽기만 한다. 배정은 **분류이지 판정이 아니다**.
