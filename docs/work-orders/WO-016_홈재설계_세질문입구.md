# 작업지시서 WO-016: 홈 재설계 — 세 질문 입구 · 진행 중 사업장 우선

- 작성일: 2026-10-02
- 작업 유형: 신규 기능
- 선행 지시서: 없음

## 1. 목적
- 홈이 **다음 행동을 고르게 하지 못한다**. 고유 목적지 29개를 읽은 뒤에야 고를 수 있고, 주력 버튼은 **입력 칸 46개**짜리 화면으로 보낸다.
- 관점 상수가 이미 담고 있는 **세 질문**을 홈의 입구로 세운다. 질문에서 시작해 답으로 끝나는 길을 만드는 것이 이 재설계의 축이다.

## 2. 배경·사용자
- 사용자 지시(2026-10-02): *「사용자가 사용할 때 경험에서 너무 어렵거나 꼬여 있어 다시 계획 잡아 보게」*
- ★사용자 결정 2026-10-02: 세 질문은 **셋 다 기본설계로** 보낸다 · 홈 첫 갈래는 **진행 중 사업장**이 위다. 290차가 비워 둔 자리다.
- 실측(`python measure_console_ia.py`): 홈 본문이 1층 화면 셋(`/design` `/flow` `/refs`)을 **하나도 링크하지 않는다**(M5=3). 보이는 입력 칸은 `/entry/newcase` **46** · `/design` **3**이다.
- 사용자: 농업인(처음 온 사람) · 투자자 · 공공기관. `PERSPECTIVES`가 정한 세 질문이 그대로 입구 문구가 된다.

## 3. 범위
- 포함: `console_home.html` 재배치 · 세 질문 입구 · 사업장 카드 우선 · 머리 메뉴·바닥글 중복 정리 · 준비물 사다리 흡수 · 가드 · 뮤테이션
- 제외: **자료 지도 통합**(WO-017) — 홈이 가리킬 자료 화면의 경로가 그 차수에 바뀐다
- 제외: **기입 통합**(WO-018) · **안내 화면 해체**(WO-019) · **날것 마크다운**(WO-020)
- 제외: **`POST /rebuild` 버튼의 확인 절차** — PRD 10절 이견으로 남긴다
- 제외: **세 번째 질문의 답을 만드는 것** — 운영 가정값이 있어야 나온다. 화면은 「여기엔 없다」로 적고 사업장 쪽을 가리킨다

## 4. 입력·출력
- 입력(전부 기존 구조): `PERSPECTIVES`(세 질문) · `READINESS_RULE`(준비물 사다리) · 케이스 목록 · `ENTRY_STEPS`(진행 띠)
- 출력: `/` 화면 — 세 질문 버튼 3 · 진행 중 사업장 카드 · 셋만 넣어 보기 · 접힘 블록(이 콘솔이 쥔 것)
- 지표: M5 `3 → 0`

## 5. 기술 조건
- **계산하지 않는다** — 카드의 수는 항목 건수 집계뿐이다(1절 258차 단서).
- **질문을 새로 쓰지 않는다** — `PERSPECTIVES`의 문구를 그대로 쓴다. 바꾸면 관점 화면과 두 갈래가 된다.
- **준비물 사다리 상수를 지우지 않는다** — 홈이 읽어 두 갈래의 안내로 쓴다.
- 접힘 블록은 스트리밍과 무관한 서버 렌더다 — `<details>`로 두고 자바스크립트를 더하지 않는다.
- 머리 메뉴·바닥글의 중복은 **바닥글을 줄이는 쪽**으로 푼다 — 머리 메뉴가 모든 화면의 기준이다.

## 6. 작업 단위 (순서대로)
- T1: 세 질문 입구 블록 — 완료 조건: 세 문구가 `PERSPECTIVES`와 한 글자도 다르지 않고 셋 다 `/design`을 가리킨다
- T2: 진행 중 사업장 카드를 첫 갈래로 · 셋만 넣어 보기를 둘째로 · 46칸 버튼을 본문에서 내림 — 완료 조건: 홈 본문에 `/entry/newcase` 링크가 없다
- T3: 세 번째 질문의 「여기엔 없다」 표기 — 완료 조건: 그 문장이 화면에 있고 사업장 쪽을 가리킨다
- T4: 숫자 띠·일하는 방식·서비스 카드·근거 현황을 접힘 블록 하나로 · 바닥글 중복 정리 — 완료 조건: 홈 본문 고유 목적지가 줄고 1층 셋이 전부 링크된다
- T5: 가드 + 뮤테이션 + 차수 기록 + PRD 표 갱신 — 완료 조건: 7절 전부 통과

## 8. 제약·주의사항
- 🔴 **질문의 배정을 내가 고르지 않았다** — ★사용자 결정 2026-10-02이다. 바뀌면 이 WO와 PRD 5절을 함께 고친다.
- 🔴 **세 번째 질문의 답을 지어내지 않는다.** 답이 없으면 없다고 적는다(1절 「근거 없는 값 금지」).
- 🔴 **어느 갈래가 낫다고 하지 않는다.** 순서는 사용자 결정이고 화면은 그 순서를 옮길 뿐이다.
- ⚠️ 홈을 건드리면 기존 가드 여럿이 함께 움직인다(플랫폼 3단계·기능 4갈래·status 분포를 홈에서 재는 단정이 있다). 지우지 말고 접힘 블록 안의 같은 값을 가리키게 옮긴다.
- ⚠️ 사용성 실측 0회다 — 두 갈래의 순서에 근거가 없다.
