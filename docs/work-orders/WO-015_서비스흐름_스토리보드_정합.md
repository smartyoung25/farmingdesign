# 작업지시서 WO-015: 화면 스토리보드 정합 — 척추 1 · 렌즈 4

- 작성일: 2026-10-02
- 작업 유형: 신규 기능
- 선행 지시서: WO-011 · WO-014

## 1. 목적
- 콘솔에 조직 축이 **다섯**인데 **무엇이 척추인지가 화면에 없다**. 서비스 설계서가 정한 **3대상 × 6단계**를 전역 화면으로 세운다.
- 단계마다 **산출물 → 기능 → 대상 → 플랫폼 → 기입 → 엔진 호출수**를 한 줄로 잇는다.

## 2. 배경·사용자
- 사용자 지시(2026-10-02): *「화면스토리보드를 최적화하고 흐름을 세부적으로 연계하고 기능을 구체적으로 매칭하여 사이트를 논리적으로 흐름에 맞게 정합적으로 서비스를 기본 구축하라」*
- 실측: 6단계(`STAGE_ORDER`)는 `lifecycle_rail()`에만 쓰이고 **케이스를 열어야 보인다**. 처음 들어온 사람은 무엇부터 볼지 알 수 없다.
- 나머지 넷(4축 `/axes` · 기능 `/functions` · 관점 `/for` · 참조 `/refs`)은 각자 화면이 있으나 **서로의 관계가 어디에도 없다**.

## 3. 범위
- 포함: 조립 계층 `service_flow()` · `/flow` 화면 · 메뉴 연결 · 사용 안내 등재 · 가드 · 뮤테이션
- 제외: **홈 재배치**(기존 가드 여럿이 함께 움직인다 — 별도 결정)
- 제외: **화면 ↔ 단계 배정**(판단이라 ★사용자 결정이 선행 — WO-016)
- 제외: **3대상 진입 경로**(WO-017) · **단계 게이트 화면**(WO-018)

## 4. 입력·출력
- 입력(전부 기존 구조): `STAGE_ORDER` · `PACKAGE_SPEC` · `PLATFORM_STAGES` · `FUNCTION_OF_CODE` · `ENTRY_STEP_*` · `GUIDE_SCREENS`
- 출력: `service_flow()` → `spine`(6단계) · `matrix`(3대상 × 6단계 건수) · `lenses`(4) · `gaps`(잇지 못한 것)

## 5. 기술 조건
- **축을 새로 만들지 않는다**(273차 — 축을 세우는 것은 ★사용자). `FLOW_TARGETS`는 `PACKAGE_SPEC`이 **이미 쓰는 값**과 같아야 한다.
- **계산하지 않는다** — 분류와 건수뿐(1절 258차 단서: 항목 건수 집계 허용).
- **없는 연결을 지어내지 않는다** — 화면↔단계 대응은 `gaps`로 드러낸다.
- 템플릿은 기존 `_base.html` 상속 · CRLF/LF 규칙은 리포 관례를 따른다.

## 6. 작업 단위 (순서대로)
- T1: `service_flow()` + `FLOW_TARGETS`·`FLOW_NO_LINK` — 완료 조건: 6단계·27산출물이 카탈로그와 한 건도 다르지 않다
- T2: `/flow` 라우트 + `service_flow.html` — 완료 조건: 200이고 매트릭스 열합계가 카탈로그 재집계와 같다
- T3: 메뉴(머리·푸터) + `GUIDE_SCREENS` 등재 — 완료 조건: 링크 2곳, 사용 안내 화면 수 +1
- T4: 가드 + 뮤테이션 + 차수 기록 — 완료 조건: 7절 전부 통과

## 8. 제약·주의사항
- 🔴 **척추를 내가 고르지 않았다** — 서비스 설계서가 3대상 × 6단계로 설계했고 화면은 그 순서를 옮길 뿐이다.
- 🔴 **어떤 단계·칸도 더 낫다고 하지 않는다.** 매트릭스의 수는 **산출물 건수**이고, 한 산출물이 여러 대상에 걸리면 여러 번 센다.
- ⚠️ 홈은 그대로 둔다 — 플랫폼 3단계·기능 4갈래로 서 있고 바꾸면 기존 가드가 함께 움직인다.
