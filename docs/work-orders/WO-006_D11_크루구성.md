# 작업지시서 WO-006: D-11 크루 구성 도입 결정 반영

- 작성일: 2026-09-28
- 작업 유형: 신규 기능
- 선행 지시서: 없음

## 1. 목적
- 결정 대기 D-11을 사용자 결정대로 반영한다. 지금 엔진은 품셈 인·일(`pumsem_project_labor_summary`)까지만 내고 **공기(캘린더 일수)는 내지 않는다** — 공기는 크루 인원으로 나눠야 나오기 때문이다.

## 2. 배경·사용자
- 사용자: 시공 공기를 검토하는 컨설턴트.
- 145차 측정: 공기 = 인·일 ÷ 크루 인원(단순 반비례). 전 품목 물량 1.0 기준 총 11.920 인·일 → 크루 8명 1.49일 · 16.4명 0.73일.
- 124차 실측 크루 범위 1.0~16.4명 → 공기가 최대 16.4배 갈린다. 🔴**크루 값을 고르는 것이 곧 공기를 정하는 것**이라 판단성이 가장 크다.
- 결정: ★**ⓒ 도입 안 함** — 사용자 결정 2026-09-28 *「D-11은 도입 안 함으로 확정해」*(255차). 선택지는 ⓐ 케이스마다 주입(엔진 기본값 없음) / ⓑ 고정값 등재(값은 사용자 지정) / ⓒ 도입하지 않음(현행 — 인·일까지만)이었다.

## 3. 범위
- 포함:
  - T1 결정 기록(세 분기 공통)
  - ⓐ·ⓑ일 때: 엔진 함수 1개 — 입력 (인·일 요약, 크루 인원) → 공기(일) · 레지스트리 등재(ⓑ는 값 status 「결정」)
  - ⓐ일 때: 케이스 저장 블록 키(근거 note 필수) — 저장 경로는 기존 `case_injections` 방식
  - 결정대기대장 D-11 닫힘
- 제외 (이번에 하지 않음):
  - 직종별 크루 구성(온실공·보통인부 등 분리) — 145차 측정이 단순 반비례만 확인했다
  - 공기를 보고서·콘솔 화면에 올리는 것(별도 WO)
  - 캘린더 일수 → 날짜 환산(휴일·기상 불가일)
  - 엔진이 크루 값을 **고르는** 모든 형태(1절)

## 4. 입력·출력
- 입력: `pumsem_project_labor_summary(quantities)` 반환의 총 인·일 · 크루 인원(양수 실수)
- 출력(인터페이스 예시만): `pumsem_schedule_days(labor_summary, crew_size) -> {"labor_days": 11.920, "crew_size": 8, "days": 1.49, "rule": "인·일 ÷ 크루 인원(145차 측정)"}` · 크루 인원이 없거나 0 이하이면 `ValueError`
- 이름·반환 키는 착수 계획에서 확정한다 [가정: 위 예시 형태]
