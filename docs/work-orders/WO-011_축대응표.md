# 작업지시서 WO-011: 축 대응표 한 장 — 산출물 코드 ↔ 단계·플랫폼·기능·기입

- 작성일: 2026-09-29
- 작업 유형: 신규 기능
- 선행 지시서: 없음

## 1. 목적
- 콘솔이 같은 산출물을 **네 이름**으로 부른다. 산출물 코드를 가운데 두고 네 축을 한 화면에 펴서, 어느 축으로 들어와도 같은 산출물에 닿게 한다.

## 2. 배경·사용자
- 사용자: 콘솔을 처음 여는 사람(컨설턴트·검토자). 지금은 홈(플랫폼축)·서비스 메뉴(기능축)·기입 허브(절차축)·케이스 레일(단계축)이 서로 다른 말을 한다.
- 273차 점검(`근거_콘솔점검_20260929.md` 1절): 축 4개 — `STAGE_ORDER` 6 · `PLATFORM_STAGES` 3 · `BENCHMARK_FUNCTIONS` 4 · `ENTRY_STEPS` 7. 데이터로는 `FUNCTION_OF_CODE`와 `PLATFORM_STAGES`로 이미 이어져 있다.

## 3. 범위
- 포함:
  - 축 대응표를 만드는 조립 함수 1개 — **있는 매핑을 펴기만** 한다
  - 축 대응표 화면 1개 + 상단 메뉴 링크
  - 각 행에서 산출물·케이스 산출물로 가는 링크
  - 가드 테스트 1건(27종 전부 네 축에 배정됐는지 · 축 정의와 화면이 갈리지 않는지)
- 제외 (이번에 하지 않음):
  - **새 축을 만드는 일**(부지·시설·장비 포함 — 축을 세우는 것은 판단성이라 ★사용자)
  - 기존 축 정의 변경(`STAGE_ORDER`·`PLATFORM_STAGES`·`BENCHMARK_FUNCTIONS`·`ENTRY_STEPS` 전부 그대로)
  - 홈·기입 허브·케이스 상세의 기존 화면 구성 변경
  - 축별 우열·추천 표시

## 4. 입력·출력
- 입력: `consulting_package`의 네 상수 + `FUNCTION_OF_CODE` + 케이스 1건의 패키지.
- 출력: 행 27개의 표. 열은 산출물 코드 · 산출물명 · 단계 · 플랫폼 · 기능 · 기입 단계. 대응이 없으면 **「대응 없음」**이라 적는다.
- 수치는 세기만 한다(앱 계층 산술 금지 — 항목 건수 집계는 258차 단서로 허용).

## 5. 기술 조건
- 언어·라이브러리: Python 3 · FastAPI · Jinja2(리포 현행). 새 의존성 추가: 금지
- 실행 환경: `python -m uvicorn webapp:app --port 8600`
- 파일 줄끝: `webapp.py`는 CRLF, `consulting_package.py`·템플릿은 LF
- 수정 금지 파일·폴더: `CLAUDE.md` 「손대지 말 것」 전체 · 엔진 · 케이스 · 레지스트리
