# 작업지시서 WO-024: 단계 게이트 조건 전사 — 설계서 §8을 산출물 표의 열로

- 작성일: 2026-10-02
- 작업 유형: 신규 기능
- 선행 지시서: WO-017

## 1. 목적
- 단계 게이트(무엇이 통과이고 무엇이 대기인가)가 **설계서 문서에만** 있다. 288차가 공백으로 남긴 자리다.
- 이 차수는 **조건만** 화면에 올린다. 「이 산출물이 나오려면 무엇이 있어야 하는가」는 설계서 글자의 **전사**이고 판정이 아니다.
- **상태(통과·대기)는 올리지 않는다** — 그것은 판정이고 선행 조건이 따로 있다(8절).

## 2. 배경·사용자
- ★사용자 결정 2026-10-02: 조건과 상태를 **둘 다** 두되 **순서가 있다**(제 추천, 채택) — 조건이 먼저, 상태는 나중이다.
- 🔴 지금 바로 통과·대기를 내면 **1절 위반**이다. 설계서 §8의 게이트가 레지스트리에 status 「결정」으로 **등재되지 않았다** — 근거 없는 판정이 된다.
- 190차 단서가 허용하는 규칙 적용형 판정의 네 조건: ①레지스트리 등재 ②결정론 ③항목별 근거 행 ④임계값 주입 가능. 지금은 ①이 비어 있다.
- 사용자: 컨설턴트와 고객이 함께 보는 자리. 「다음에 무엇이 있어야 넘어가는가」를 말로 설명하지 않게 한다.

## 3. 범위
- 포함: 설계서 §8 조건의 전사 · 산출물 표의 조건 열 · 전사 출처 표기 · 가드 · 뮤테이션
- 제외: **상태(통과·대기) 표시** — 판정이고 레지스트리 등재가 선행한다. 별도 차수다
- 제외: **게이트의 레지스트리 등재** — 등재는 값의 성격을 정하는 일이라 ★사용자 결정이 선행한다
- 제외: **임계값 신설** — 설계서에 없는 조건을 만들지 않는다
- 제외: **케이스별 판단** — 이 화면은 케이스 없이 선다

## 4. 입력·출력
- 입력: 서비스 설계서 §8의 게이트 문장 · `PACKAGE_SPEC`의 산출물 27종 · `STAGE_ORDER`
- 출력: 산출물 표의 조건 열 — 산출물마다 「넘어가려면 무엇이 있어야 하는가」와 그 문장의 **출처(문서·절)**
- 지표: 걸지 않는다 — 전사의 완전성은 가드가 설계서 쪽수·절 번호로 센다

## 5. 기술 조건
- 🔴 **전사이고 요약이 아니다** — 설계서의 문장을 줄여 쓰지 않는다. 줄이면 그것이 내 판단이 된다(205차 교훈: 요약은 썩는다).
- **출처를 함께 적는다** — 문서명과 절 번호를 조건마다 붙인다. 없는 조건은 「설계서에 없음」으로 적는다.
- **판정 어휘를 쓰지 않는다** — 「통과」·「대기」·「충족」을 이 차수의 화면에 쓰지 않는다. 조건만 적는다.
- **계산하지 않는다** — 조건의 개수 집계까지만 한다(1절 258차 단서).
- 조건이 비는 산출물이 있을 수 있다 — **비는 것을 비었다고 적는다**.

## 6. 작업 단위 (순서대로)
- T1: 설계서 §8을 열어 조건 문장을 전수로 뽑는다 — 완료 조건: 뽑은 수와 설계서의 수가 같고 요약한 것이 0건이다
- T2: 산출물 표의 조건 열 + 출처 표기 — 완료 조건: 조건마다 문서·절이 붙고 없는 것은 「설계서에 없음」이다
- T3: 가드 + 뮤테이션 + 차수 기록 + PRD 갱신 — 완료 조건: 7절 전부 통과

## 8. 제약·주의사항
- 🔴 **상태를 내지 않는다.** 통과·대기는 판정이고, 190차 네 조건 중 **레지스트리 등재가 비어 있다**. 조건 전사와 상태 판정을 같은 차수에 섞으면 근거 없는 판정이 화면에 나간다.
- 🔴 **설계서에 없는 조건을 만들지 않는다.** 비면 비었다고 적는다.
- 🔴 **요약하지 않는다.** 전사한 문장이 원문과 글자가 같아야 하고 가드가 그것을 잰다.
- ⚠️ 상태 판정은 **다음 차수의 일**이고 선행은 ★사용자 결정(게이트를 레지스트리에 등재할지, 임계값을 무엇으로 둘지)이다.
- ⚠️ 설계서 원문이 리포에 있는지 먼저 확인한다 — 없으면 이 차수는 **자료 대기**로 멈추고 그 사실을 적는다.
