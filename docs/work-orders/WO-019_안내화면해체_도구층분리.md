# 작업지시서 WO-019: 안내 화면 해체 — 도구층 분리

- 작성일: 2026-10-02
- 작업 유형: 리팩터링
- 선행 지시서: WO-016 · WO-017 · WO-018

## 1. 목적
- 화면 21개를 설명하려고 **스물두 번째 지도**가 생겼고, 그 지도의 링크 21개 중 **여덟이 열리지 않는다**. 앞의 세 WO가 끝나면 설명할 화면이 아홉이라 지도 자체가 필요 없어진다.
- 🔴 열리지 않던 링크 여덟은 **WO-020이 먼저 닫는다**(★사용자 결정: 표시 위생 먼저). 이 차수는 그 화면 자체를 없애므로 그 줄들도 함께 사라진다.

## 2. 배경·사용자
- ★사용자 결정 2026-10-02: 전면(21→9) · `/guide`를 없앤다
- 실측(`python measure_console_ia.py`): 사용자가 세는 화면 **21**(M1) · 열리지 않는 링크 **8**(M2). 안내 화면 본문은 9,995자이고 함수명 스무 개·파일명 열아홉 개가 노출된다.
- 원인: 안내 화면이 등재 경로 문자열을 **그대로 주소에 썼다**. 자리표시자가 담긴 경로는 실제 코드로 바꿔야 열린다.
- 작업지시서·견적 전사는 **세 관점 질문 어디에도 걸리지 않는다** — 만드는 쪽 도구다. 지금은 고객용 근거대장과 나란히 메뉴에 있다.

## 3. 범위
- 포함: 안내 화면 해체 · 화면별 설명을 각 화면 부제로 · 자주 묻는 것 열넷 분산 · 도구층 세 화면 분리 · 등재·파리티 가드 갱신 · 뮤테이션
- 제외: **자주 묻는 것의 내용 수정** — 문구를 고치지 않고 자리만 옮긴다
- 제외: **도구층 화면의 내용 변경** — 경로와 메뉴 위치만 바꾼다
- 제외: **참조 화면 구조**(별도) · **날것 마크다운과 링크 여덟**(WO-020이 먼저 한다)
- 제외: **앞 세 WO가 끝나기 전 착수** — 설명이 먼저 사라지면 되돌릴 근거가 없다

## 4. 입력·출력
- 입력(전부 기존 구조): `GUIDE_SCREENS`(등재 21) · 자주 묻는 것 여덟 · 질의응답 여섯 · 화면별 설명
- 출력: 등재 화면 아홉 · 각 화면 머리의 한 줄 부제 · 그 화면 안의 접힘 블록으로 옮긴 묻는 것 · 도구층 세 화면
- 지표: M1 `21 → 9`(M2는 WO-020이 닫는다)

## 5. 기술 조건
- **등재 목록을 지우지 않는다** — 아홉으로 줄이고, 라우트↔등재 파리티 가드를 아홉 기준으로 갱신한다. 목록이 사라지면 화면 수가 다시 늘어도 아무도 모른다.
- **자리표시자를 담은 경로는 주소로 쓰지 않는다** — 실제 코드로 바꿔 걸거나, 거는 대신 「코드를 골라야 열린다」고 적는다.
- **묻는 것의 문구를 바꾸지 않는다** — 자리만 옮긴다. 바꾸면 내용 검증이 함께 필요해진다.
- **도구층은 경로 접두로 가른다** — 머리 메뉴에서 내리고, 주소를 가진 사람이 막히지 않게 안내를 남긴다.
- 화면 부제는 등재 목록의 설명을 **그대로** 쓴다 — 요약하지 않는다(205차 교훈: 요약은 썩는다).

## 6. 작업 단위 (순서대로)
- T1: 등재 목록을 아홉으로 · 파리티 가드 갱신 — 완료 조건: M1이 9이고 라우트와 등재가 서로 빠짐없이 대응한다
- T3: 화면별 설명을 각 화면 부제로 — 완료 조건: 아홉 화면 전부에 부제가 있고 등재 설명과 한 글자도 다르지 않다
- T4: 묻는 것 열넷을 답이 쓰이는 화면으로 분산 — 완료 조건: 열넷이 하나도 사라지지 않았다
- T5: 도구층 세 화면 분리 + 안내 화면 제거 — 완료 조건: 도구층이 머리 메뉴에 없고 세 화면이 200이다
- T6: 가드 + 뮤테이션 + 차수 기록 + PRD 표 갱신 — 완료 조건: 7절 전부 통과

## 8. 제약·주의사항
- 🔴 **앞 세 WO가 끝나기 전에 착수하지 않는다.** 설명이 먼저 사라지면 되돌릴 근거가 없다.
- 🔴 **등재 목록을 없애지 않는다.** 아홉으로 줄이는 것과 목록을 지우는 것은 다르다 — 목록이 없으면 화면 수가 다시 스물로 늘어도 가드가 침묵한다.
- 🔴 **묻는 것을 「없어도 된다」며 버리지 않는다.** 열넷은 사용자가 실제로 막힌 자리의 기록이다.
- ⚠️ 등재 수를 세던 가드가 여럿이다. 수를 바꾸는 차수는 작업지시서 2절 스냅샷을 같은 커밋에서 갱신한다.
- ⚠️ 안내 화면이 「여기에 없는 화면이 있으면 가드가 실패한다」로 설계됐으나, 그 설계는 **문서 의무만 강제하고 화면 수는 제한하지 않았다** — 17에서 21까지 늘어난 기록이 주석에 그대로 있다. 아홉으로 줄인 뒤 상한을 함께 박는다.
