# 작업지시서 WO-020: 표시 위생 — 날것 마크다운 · 자기 모순 문장 · 열리지 않는 링크 여덟

- 작성일: 2026-10-02
- 작업 유형: 버그 수정
- 선행 지시서: 없음

## 1. 목적
- 레지스트리·조립 계층의 서술에 쓰인 마크다운이 콘솔 화면에 **글자 그대로** 나간다 — 별표 **552개** · 백틱 **196개**. 참조 화면 한 곳에만 별표 300개다.
- 흐름 화면이 한 화면 안에서 **자기 말을 뒤집는다** — 대응표는 「확인 필요 0」이라 적고, 같은 화면 아래 문단은 「기본설계 화면은 확인 필요」라 적는다. 함수 반환은 빈 목록인데 문장이 상수에 박혀 있다.
- 사용 안내 화면이 가리키는 **스물한 곳 중 여덟이 열리지 않는다**. 등재 경로 문자열을 그대로 주소에 써서 자리표시자가 주소로 나간다.

## 2. 배경·사용자
- ★사용자 결정 2026-10-02: 표시 위생을 **먼저** 한다 — 날것 마크다운에 대해 *「오탈자부터 개선하고 진행하자」*. 링크 여덟을 같은 차수에 넣은 것은 제 추천이고 사용자가 *「추천하라」*로 맡겼다.
- 실측(`python measure_console_ia.py`): 별표 **552**(M3) · 백틱 **196**(M4) · 자기 모순 2건(M8). ⚠️297차에 측정 상태를 **결과가 나온 화면**으로 통일해 534·194에서 552·196이 됐다 — 작업이 아니라 측정 범위의 정정이다.
- 148차가 정적 사이트의 리터럴 마크다운을 **3,833 → 2**로 닫았다. 그 작업은 `build_site` 생성기를 고쳤고 **콘솔은 덮이지 않았다**.
- ⚠️ 148차가 콘솔을 범위에 뒀는지는 **근거 문서를 열어 확인해야 한다** — 이 WO의 첫 작업 단위가 그것이다.
- 사용자: 화면을 읽는 사람 전부. 붉은 동그라미 기호는 코드 주석의 자기 지시인데 고객 화면의 본문 어조가 되어 있다.

## 3. 범위
- 포함: 콘솔 화면의 인라인 마크다운 렌더 · 자기 모순 문장 두 곳 · **열리지 않는 링크 여덟** · 가드 · 뮤테이션
- 제외: **레지스트리 문자열 수정** — 버그는 렌더 계층에 있다. 레지스트리를 고치면 값 변경 차수가 되고 원문 대조가 필요하다
- 제외: **라우트 변경·화면 통합**(WO-016~019) — 섞으면 회귀 원인을 가릴 수 없다. 링크 여덟은 **표시 쪽**이라 여기 들어간다
- 제외: **사용 안내 화면의 해체**(WO-019) — 🔴그때 그 링크들은 함께 사라지므로 여기서 고치는 줄은 **버려진다**. 그래도 먼저 고치는 이유는 네 차수가 남아 있기 때문이다
- 제외: **치수 표기를 이탤릭으로 해석하는 것** — 148차가 이미 막았다. 규격 토큰이 사라진다
- 제외: **붉은 동그라미 기호를 전부 없애는 것** — 어느 기호가 고객 화면에 맞는지는 ★사용자 결정이다. 이 차수는 렌더만 고친다

## 4. 입력·출력
- 입력: 콘솔 템플릿이 렌더하는 문자열 전부 · 148차가 만든 인라인 렌더 규칙 · `screen_stage_map()`의 반환
- 출력: 태그 제거 후 본문에 별표·백틱이 남지 않는 화면 일곱 · 반환에서 파생하는 공백 문장
- 지표: M2 `8 → 0` · M3 `552 → 0` · M4 `196 → 0` · M8 `2 → 0`(렌즈 라벨 한 건은 WO-017이 닫는다)

## 5. 기술 조건
- **148차의 렌더 규칙을 다시 만들지 않는다** — 이미 있는 것을 콘솔이 쓰게 한다. 두 벌이 되면 한쪽만 고쳐지는 자리가 생긴다.
- **코드 스팬 안의 별표는 남을 수 있다** — 그것은 글자 그대로가 맞다. 가드는 코드 스팬 밖만 센다.
- **치수 표기를 깨뜨리지 않는다** — 단일 별표 이탤릭은 지원하지 않는다(148차 결정).
- **공백 문장은 반환에서 파생한다** — 상수에 문장을 박지 않는다. 박으면 292차처럼 반환이 바뀌어도 문장이 따라오지 않는다.
- 가드는 **실측기를 불러** 수를 다시 센다 — 가드 안에 숫자를 적으면 숫자 둘이 생긴다.

## 6. 작업 단위 (순서대로)
- T1: 148차 근거 문서를 열어 콘솔이 범위였는지 확인 — 완료 조건: 범위였는지 아닌지를 차수 기록에 적었다
- T2: 콘솔이 인라인 렌더 규칙을 쓰게 한다 — 완료 조건: M3·M4가 0이고 코드 스팬 안은 그대로다
- T3: 치수 표기 회귀 확인 — 완료 조건: 규격 토큰이 하나도 사라지지 않았다
- T4: 공백 문장을 반환에서 파생 — 완료 조건: 반환이 비면 문장도 「확인 필요」를 적지 않는다
- T5: 자리표시자 링크 여덟을 실제 코드로 — 완료 조건: M2가 0이다
- T5: 가드 + 뮤테이션 + 차수 기록 + PRD 표 갱신 — 완료 조건: 7절 전부 통과

## 8. 제약·주의사항
- 🔴 **레지스트리 문자열을 고치지 않는다.** 버그는 렌더 계층이다. 값을 고치면 원문 확보·대조가 필요한 차수가 된다(1절).
- 🔴 **라우트 변경과 같은 차수에 섞지 않는다.** 섞으면 회귀가 어디서 났는지 가릴 수 없다.
- 🔴 **단일 별표 이탤릭을 지원하지 않는다.** 치수 표기 네 문자열이 깨진다(148차·156차에 두 번 확인했다).
- ⚠️ 148차가 콘솔을 범위에 뒀는지 모른 채 「덮이지 않았다」고 단정하지 않는다 — T1이 그것을 확인한다.
- ⚠️ 가드 안에 552·196을 적지 않는다. 실측기를 불러 세고, 목표는 0이라는 사실만 단정한다.
