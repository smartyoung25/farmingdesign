# 레드팀 패스 (fresh-context 대조 리뷰)

절차·루브릭의 **단일 출처는 `검증절차_레드팀.md`** 다 — 이 스킬은 그 절차의 실행기다.
실행 전 그 문서의 "원칙(생략 금지)"과 "루브릭 v1"을 읽어라.

## 실행 순서

1. **대상 선정**: 이번에 데이터가 바뀐 산출물(케이스 JSON·견적비교 JSON·레지스트리·생성 HTML).
   기준 문서 = 해당 원문 파일(source_file·source_refs) + SmartFarm_근거대장.html + 작업지시서 1절.
2. **기계 게이트 선행**: `python -m pytest test_engine.py test_registry.py test_cases.py test_chunking_v2.py test_webapp.py -q`
   green + `python audit_traceability.py` PASS 확인 — 레드팀은 기계 검증 위에서 의미 결함만 본다.
3. **fresh-context 에이전트 실행**(Explore 계열, read-only). 프롬프트 골격:

   ```
   [fresh-context 레드팀 리뷰 — 이 대화 이전의 맥락은 없다고 가정하라. 너는 이 산출물을 만들지 않았다.]
   {산출물}을 {기준 문서}에 대조해 리뷰하라.
   1. 모든 수치를 원본에서 직접 재추출·재계산해 원단위 대조(불일치는 [산출물 값|원본 값|위치]).
      xls가 깨지면 chunking_lib_v2._xls_sheets_lenient로 관대 파싱, 실패는 실패로 기록(추측 금지).
   2. 주요 수치·주장에 [주장]|[출처]|[등급: 1차/2차/미확인]|[반대근거] 4열표.
   3. 등급 약한 항목이 본문에서 단정문이 됐는가(최중요). 총액류는 원가 계층 동일성까지.
   4. 판정·추천 어휘 유입 여부("추천 없음" 명시 확인).
   5. 명시 요구 누락·범위 밖 변경.
   스타일 취향이 아니라 "빠진 것"을 보고해.
   정확성이나 명시된 요구사항에 영향을 주는 갭만 flag해.
   발견이 없으면 "발견 없음"이 정답이다 — 지어내지 마라.
   확인하지 못한 것은 "확인 불가(사유)"로 명시하라.
   ```

4. **발견 채택 전 독립 재검증**: 핵심 주장(셀·페이지)은 메인 세션이 원문에서 직접 재확인한다 —
   레드팀 발견도 검증 대상이다.
5. **분류 후 조치**: 결정론 결함(소규모=동일 차수 수정, 대규모=별도 차수) / 시세성·판단성(사용자
   이관) / 거짓 양성(루브릭 개정 근거). FAIL 3연속이면 루브릭 자체를 의심.
6. **기록**: `검증절차_레드팀.md` 실행 기록에 회차 추가(대상·통과·발견·거짓 양성·조치) +
   작업지시서 갱신 이력(검증한 것/안 한 것) + 차수 커밋.
