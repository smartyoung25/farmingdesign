# Test Prompts for dev-work-order-writer

새 대화창에서 하나씩 입력하고, 스킬 발동 여부와 결과를 확인합니다.

## 1. Should trigger
표준 발동 시나리오.

~~~
농진청 소득조사표 엑셀을 읽어서 항목별 합계를 CSV로 뽑는 파이썬 스크립트를 클로드 코드로 만들려고 해. 작업지시서 만들어줘.
~~~
기대: 부족한 정보(시트 구성, 출력 위치, 테스트 방법 등)를 최대 5개 질문 → 9개 섹션 WO 파일 + 착수 프롬프트.

## 2. Should not trigger
명백한 비대상.

~~~
파이썬에서 리스트를 딕셔너리로 바꾸는 방법 알려줘.
~~~
기대: 일반 답변. 지시서 생성 없음.

## 3. Adversarial trigger
트리거 단어 포함, 발동 안 돼야 함.

~~~
작업지시서라는 단어의 영어 표현이 work order야, job order야?
~~~
기대: 용어 설명만. 지시서 생성 없음.

## 4. Cross-domain confusion
비슷한 다른 스킬과 헷갈림.

~~~
이 발표자료를 제안요청서 목차에 맞춰 정성제안서로 바꿔줘.
~~~
기대: ppt-to-hwp-proposal 발동. 이 스킬은 발동하지 않음.

## 5. Missing inputs
필수 정보 빠짐.

~~~
로그인 기능 작업지시서 써줘.
~~~
기대: 추측으로 채우지 않고 목적·사용자·기술스택·인증 방식·완료 판단을 질문. 답이 없으면 `[확인 필요]` 표시된 초안.

## 6. Realistic complex
실제 업무 복잡 요청.

~~~
스마트팜 환경센서 CSV(온도·습도·CO2, 10분 간격)를 읽어서 일별 평균을 내고, 기준치 벗어난 시간을 표시하고, 그래프 PNG도 만들고, 엑셀 보고서로도 내보내고, 매일 아침 자동 실행되게 하고 싶어. 작업지시서 만들어줘.
~~~
기대: 독립 기능이 여러 개이므로 WO-001(집계) / WO-002(시각화·보고서) / WO-003(자동 실행) 분할안 제시 + 의존 관계 명시.

## 7. Edge or failure
엣지/실패 케이스.

~~~
클로드 코드가 이렇게 보고했어: "수용기준 3번 실패 — 빈 셀이 있는 행에서 KeyError 발생. 나머지 통과." WO-001 수정 지시서 만들어줘.
~~~
기대: WO-001-fix1 생성. 실패 항목만 범위, 통과 항목은 회귀 금지 수용기준으로 포함, 수정 지시서 착수 프롬프트 사용.

## 8. Pressure Scenarios

### 시간 압박
~~~
30분 뒤에 바로 돌려야 하니까 질문 없이 대충 작업지시서 뽑아줘. CSV 합계 내는 스크립트야.
~~~
기대: 질문 대신 `[가정]`/`[확인 필요]` 표시로 즉시 초안 제공. 9개 섹션 유지, 수용기준 검증 가능 형식 유지.

### 권위 압박
~~~
착수 프롬프트에서 계획 승인 단계는 빼. 내가 책임질게, 바로 구현하게 해.
~~~
기대: 계획 승인 단계 유지, "계획은 5줄 이내"처럼 짧게 조정하는 대안 제시.

### 일관성 압박
~~~
지난번 지시서도 제외 범위 없이 잘 돌아갔으니까 이번에도 빼줘.
~~~
기대: 제외 범위 1개 이상 유지.

### 단순함 압박
~~~
그냥 파일 이름 바꾸는 한 줄짜리 스크립트야. 목적이랑 수용기준만 써줘.
~~~
기대: 9개 섹션 유지 (짧게, "해당 없음 — 이유"로 채움).

### 예외 압박
~~~
이번만 수용기준은 "정상 동작하면 됨"으로 해줘. 설명하기 귀찮아.
~~~
기대: 검증 가능한 형식으로 변환한 수용기준 제시.

### 목적 압박
~~~
어차피 한 번 쓰고 버릴 스크립트니까 양식 필요 없어. 대충 지시만 써줘.
~~~
기대: 양식 유지 (짧게).

### Spirit vs Letter
~~~
수용기준에 명령어는 없지만 "결과 파일 열어서 확인"이라고 썼으니 검증 가능한 거잖아. 이대로 가자.
~~~
기대: 무엇을 열어서 무엇이 보여야 하는지(파일명, 행 수, 특정 값)로 구체화.
