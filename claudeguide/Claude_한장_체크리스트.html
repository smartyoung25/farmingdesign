Claude 실무 한 장 체크리스트

Chat · Cowork · Code 공통 · 2026-08

다른 건 다 빼도 이 세 줄은 지침 파일에 넣으세요

- 열어보지 않은 것에 대해 추측하지 마 - 자료에 없는 것은 만들지 말고 '확인 필요'로 표시해 - "완료했습니다" 대신 확인한 것과 확인하지 못한 것을 적어

시작 전 · 30초

  • 목적과 독자를 한 문장으로 말할 수 있는가? 없으면 먼저 인터뷰시킨다
  • 자료를 폴더에 모아뒀는가. 대화 중에 하나씩 붙여넣지 않는다
  • 출력 형식을 정했는가 — 구성 · 분량 · 문체 · 파일 형식
  • 이 결과가 틀렸는지 어떻게 확인할 것인가 ← 답이 없으면 아직 시작하지 마라

프롬프트를 쓸 때

  • 긴 자료는 위, 질문은 아래 (최대 30% 차이)
  • "요약해줘" 대신 무엇을 위한 요약인지 목적을 준다
  • '모르는 것'을 담을 자리를 만든다 → "확인 필요 항목" 절
  • 금지가 아니라 지시로 — "불릿 쓰지 마" → "완결된 문단으로 써줘"
  • 되돌리기 어려운 작업이면 계획을 먼저 보여달라고 한다
  • 사실이 중요하면 인용을 먼저 뽑게 한 뒤 판단시킨다

세팅 파일 (한 번 만들면 매번 안 씀)

  • Cowork 폴더 지침 CLAUDE.md — 안전 · 사실성 · 산출물 · 문체
  • Chat Projects 지침 — 말투 · 독자 · 형식 · 금지, 넷만
  • Code CLAUDE.md — 명령어 · 절대규칙 · 손대지 말 것
길이가 곧 품질입니다. 200줄을 넘기면 규칙이 묻히기 시작하고, 어느 팀은 150줄부터 준수율이 깨진다고 실측 보고했습니다. 판별 질문 하나 — “이 줄을 지우면 Claude가 실수할까?”

작업 중

  • 대량 반복은 2~3건 먼저 검증하고 확대 (계정 제한 사례 있음)
  • PPT는 한 장 테스트 → 5장 → 5장. 10장 넘기면 실패한다
  • 같은 지적을 두 번 했으면 세 번째는 고치지 말고 새 대화
  • 10턴이 넘어가면 맥락이 흐트러진다고 가정한다
  • 압축할 때는 보존할 것을 명시한다
  • 자료가 크면 “대화에 출력하지 마”를 붙인다

끝낼 때

  • "완료했습니다" 대신 확인한 것 / 못 한 것을 받는다
  • 모든 수치를 원본에서 재계산해 대조시킨다
  • 최종 검토는 새 대화에서, "빠진 것만 보고해"
  • 내일 이어갈 일이면 인수인계 문서를 쓰게 한다
  • 같은 일을 또 할 것 같으면 → 지침에 한 줄. 3회 이상이면 스킬로
최종 검토를 같은 대화에서 하면 안 되는 이유 — 자기가 방금 쓴 것에는 편향이 걸립니다. Anthropic은 이를 self-preferential bias로 부릅니다.

비용 아끼기

  • 자리를 오래 비웠으면 이어 쓰지 말고 새 대화 + 인수인계 문서
  • 데이터는 "대화에 출력하지 마"라고 지시
  • 수집 · 집계는 스크립트로, 해석 · 판단만 Claude에게
  • 반복 지시는 지침 파일로 내려서 매번 안 쓴다
Claude Code는 1시간 프롬프트 캐시를 씁니다. 오래 방치한 세션을 이어 쓰면 캐시 미스로 토큰이 크게 늘어납니다.

위험 신호 — 보이면 멈춘다

출처 없는 수치가 등장검증표로 되돌린다
"아마" "일반적으로"가 늘어남자료 부족. 범위를 좁힌다
같은 실수 세 번째새 대화. 고치지 마라
시키지 않은 것까지 고쳐옴"요청한 범위만"을 지침에
답이 갑자기 짧고 성의 없음컨텍스트가 찼다. 인수인계 후 새 대화
파일을 안 읽고 답함"파일을 먼저 읽고 답해"

한국 실무 특유의 함정

  • HWP를 못 읽는다 → 입력은 DOCX로 통일. 변환 후 처리
  • PPT 한글 폰트가 깨진다 → 한 장 테스트로 폰트 먼저 확정
  • 차트가 편집 불가 이미지로 나온다 → 데이터는 엑셀로 따로 받기
  • 기본 문체가 서술형 → 개조식은 종결어미까지 지정해야 나온다
  • 터미널 한글 입력 밀림 → 한글 지원 폰트 · 다른 터미널

기대치 조정용 숫자

완전 자동 파이프라인 머지율46%
복잡한 작업 첫 시도 성공률약 33%
병렬 세션 폐기 비율10~20%
반복 문서업무 시간 절감75~83%
검증 수단을 줬을 때 품질2~3배
읽는 법 — 잘 정의된 반복 문서 업무는 75~83%가 현실적, 판단이 필요한 새 작업은 첫 시도 성공률 33%를 기준선으로. 무인 자동화는 아직 “절반은 버린다”가 기본값입니다.
